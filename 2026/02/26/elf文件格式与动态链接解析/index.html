elf文件格式与动态链接解析

ELF文件件格式与动态链接解析

PART1 ELF文件格式

ELF代表Executable and Linkable Forma，是一种对可执行文件、目标文件和库使用的文件格式，ELF格式是是UNIX系统实验室作为ABI（Application Binary Interface）而开发和发布的，是Linux系统的标准文件格式了。与Windows下的PE文件格式类似。 本文使用如下的简单程序来具体讲述ELF文件的格式，建议对照着程序的二进制码阅读本文。

一. ELF概述

ELF主要包括三种类型文件：

  • 可重定位文件(relocatable)：编译器和汇编器产生的.o文件，被Linker所处理
  • 可执行文件(executable)：Linker对.o文件进行处理输出的文件，进程映像
  • 共享对象文件(shared object)：动态库文件.so

下面是三种类型的示例:

ELF文件布局 ELF文件包括了5个部分：

  • ELF header，描述体系结构和操作系统等基本信息，指出section header table和program header table在文件的位置

  • program header table，这个是从运行的角度来看ELF文件的，主要给出了各个segment的信息，在汇编和链接过程中没用

  • section header table，这个保存了所有的section的信息，这是从编译和链接的角度来看ELF文件的

  • sections，就是各个节区

  • segments，就是在运行时的各个段

ELF布局图：

由图可以知道，其实sections和segments占的一样的地方。这是从链接和加载的角度来讲的。左边是链接视图，右边是加载视图，sections是程序员可见的，是给链接器使用的概念，而segments是程序员不可见的，是给加载器使用的概念。一般是一个segment包含多个section。Windows的PE就没有这个program header table和section header table点都统一为section，只是在加载时会进行处理。所以program header table和section header table都是可选的。

二. ELF的组成结构

(1) ELF header

ELF Header描述了体系结构和操作系统等基本信息,并指出Section Header Table和Program Header Table在文件中的什么位置，每个成员的解释参见注释。

为了方便参考，将上面结构体用表格形式表示如下： | 字段名 | 数据类型 | 说明 | | :--- | :--- | :--- | | e_ident | unsigned char[EI_NIDENT] | ELF的一些标识信息，固定值 | | e_type | Elf32_Half | 目标文件类型：1-可重定位文件，2-可执行文件，3-共享目标文件等 | | e_machine | Elf32_Half | 文件的目标体系结构类型：3-intel 80386 | | e_version | Elf32_Word | 目标文件版本：1-当前版本 | | e_entry | Elf32_Addr | 程序入口的虚拟地址，如果没有入口，可为0 | | e_phoff | Elf32_Off | 程序头表(segment header table)的偏移量，如果没有，可为0 | | e_shoff | Elf32_Off | 节区头表(section header table)的偏移量，没有可为0 | | e_flags | Elf32_Word | 与文件相关的，特定于处理器的标志 | | e_ehsize | Elf32_Half | ELF头部的大小，单位字节 | | e_phentsize | Elf32_Half | 程序头表每个表项的大小，单位字节 | | e_phnum | Elf32_Half | 程序头表表项的个数 | | e_shentsize | Elf32_Half | 节区头表每个表项的大小，单位字节 | | e_shnum | Elf32_Half | 节区头表表项的数目 | | e_shstrndx | Elf32_Half | 某些节区中包含固定大小的项目，如符号表。对于这类节区，此成员给出每个表项的长度字节数。 |

特别注意最后一个字段e_shstrndx的含义：“e_shstrndx”是“Section header string table index”的缩写。段表字符串表本身也是ELF文件中的一个普通的段，它的名字往往叫做“.shstrtab”。那么这个“e_shstrndx”就表示“.shstrtab”在段表中的下标，即段表字符串表在段表中的下标。

(4) section segment关系

ELF 文件中的 Section（节）和 Segment（段）是从不同视角看待同一个文件的方式，多个 Section 在运行时被合并、映射，形成一个 Segment。

Section 是链接时的概念，而 Segment 是运行时的概念。

🔍 两种视角 | 维度 | Section (节) | Segment (段) | | :--- | :--- | :--- | | 视角 | 链接视图 (Linking View) | 执行视图 (Execution View) | | 目的 | 为链接器和调试器服务，精细组织代码和数据（如 .text, .data, .symtab）。 | 为操作系统加载器服务，定义如何将文件内容映射到内存中。 | | 使用者 | 链接器 (ld)、调试器 (gdb) | 操作系统内核、动态链接器 | | 生命周期 | 主要存在于文件中，链接时使用。部分 .debug 等信息在程序运行时通常被丢弃。 | 从文件加载到内存开始，贯穿进程的整个生命周期。 | | 描述表 | 节头表 (Section Header Table)，由 e_shoff 字段定位。 | 程序头表 (Program Header Table)，由 e_phoff 字段定位。 |

🧩 组成与映射关系

一个 Segment 通常由一个或多个具有相同内存访问权限的 Section 组成。

映射过程：当操作系统加载 ELF 文件时，它会读取程序头表，根据表中的信息，将文件中一个或多个 Section 的内容加载到内存的同一个连续区域，并赋予相同的权限（如可读、可写、可执行），这个内存区域就是一个 Segment。 并非所有 Section 都会被加载：只有那些具有 ALLOC（分配）属性的 Section 才会被纳入某个 PT_LOAD 类型的 Segment 中。例如，存放符号表的 .symtab 和调试信息的 .debug 节通常只在链接和调试时需要，不会被加载到内存中运行，因此它们不属于任何 Segment。 下图为elfExample文件section和segment映射关系。
